## 背景与目标

用户是做 EDA 的研究生，课题是在 AIG 上做 rewrite 的全局联合选择。仓库是 GitHub Appleeyelala/CULS\_LiteCut，旧分支有 work/paper-joint-evidence 和 work/diagnose-proxy-joint，当前工作分支是 work/abc-candidate-export。用户用中文交流，要求说明用大白话，计划要短、一步一步来。

**旧方向（已汇报，结论可直接引用）**：用 LiteCut 估计局部延迟，MFFC 分区并行，GPU 上做可微的全局时序代理，用梯度联合选择 rewrite 候选，最后用真实 ABC 映射验收。

- 相对原图快约 5.5%（外部 24 个电路，−5.48%）；相对 ABC rewrite 没有稳定优势（外部 −1.28%，10/24 更快，置信区间跨 0；开发集 +8.74%）。
- 运行时间：外部中位约 22 倍于一次 rewrite，开发集中位约 120 倍。
- 代理不准：零编辑延迟误差平均 43%，编辑收益排序的 Spearman 0.59。
- 局部收益不可相加：intra\_pred\_PE 上 8 个单独有利的编辑组合后反而变慢；c5315 上单独都没用的编辑组合后有协同收益。

- 详细进度汇报文档：https://claude.ai/artifact/KBCqNHSY5RGYNosdumFMhB。

**老师的新方向（2026-11-20 确定）**

1. 并行指多条 PI→PO 路径并行。同一个 MFFC 里有多条路径从不同输入进来、从同一个 root 出去，对 MFFC 里一个 cut 做 rewrite 要同时兼顾这几条路径。
2. 候选得分是各路径延迟的加权和。WNS 路径权重更大；之后可试软权重 w = exp(−slack/τ)，slack = 要求时间 − 到达时间。
3. 第一版只在 AIG 层做，不做 mapping，延迟用 level（路径上 AND 节点数）代替，暂时不用 LiteCut 和代理。

**用户原始的设想**（一定要记住，这是评价标准的来源）：多条路径可能同时经过一个 cut，这个 cut 的 rewrite 会同时影响它们。其中一条可能是 WNS 路径，影响很大；另一条很短，即使变长也只影响 TNS、不影响 WNS。所以目标是从整体角度降低 level，而不是只看最长的那一条。

**结构依据**：MFFC 是对 AND 节点的分区，互不重叠；内部（非 root）节点的所有扇出都在本区域里，所以路径一定从 root 离开，延迟只通过 root 在区域之间传递。

**最终验收**仍用真实 ABC 映射和 CEC，但不放进优化循环，只用来检验“AIG 层 level 变小是否真的让映射后延迟变小”。比较对象是 ABC 自带 rewrite，以及加权方案和不加权方案。

## 当前结论

**总结**：ABC rewrite 在关键节点上留下了降低 level 的局部空间，加权明显好于不加权的 Σd。但加权相对更简单的“只最小化 root 新 level”是否有额外价值、全局是否真的变快，都还没有证据。

**已经站得住的（我都独立重算过）**

1. ABC 默认规则隐藏了绝大多数候选：4 个试点里 958,897 个候选只有约 7% 会被默认接受。
2. 关键节点（slack=0，5,212 个非空决策）上，ABC 默认只在 8.9% 的决策里降低 level，91.1% 保持原结构。
3. 加权显著好于不加权求和：不加权在关键节点上有 14.1% 的决策会让 root 变深并破坏时序余量，加权只有约 1%。

| --- | --: | --: | --: |
| 不加权 Σd | 20.9% | 14.1% | 53.1% |
| 硬权重 | 42.1% | 1.1% | 51.7% |
| 软权重 τ=0.5 / 1 / 2 | 41.3% / 41.3% / 41.2% | 1.2% / 1.2% / 1.5% | 54.2% / 54.3% / 54.4% |
| rootlevel（只最小化 root 新 level） | 42.9% | 0.4% | 49.8% |
| abc\_default | 8.9% | 0% | 0% |

**尚未证实的**

1. **全局收益。** 没有安装过任何候选，没有在改写后的图上重算 level，所有“降低”都是局部预测。局部降低不等于全局降低（关键决策只占 3.5%，且同一节点有多个 cut、相邻改写互相重叠），用户自己的旧发现也是“局部收益不可相加”。
2. **加权 vs rootlevel。** 上表里 rootlevel 在“降低”和“面积”上都不输加权，但这把尺子本身就是 rootlevel 直接优化的目标，不公平。root\_level 是所有叶子路径到达 root 的最大值，属于 WNS 型的量，没有测 TNS。用户的原始设想正是“最长路径重点压，接近最长的路径也别变长”，所以 v3 (A) 补了 TNS 型指标。
3. **v3 (A) 的结果（workbuddy 报告，我没核对）**：在 root\_level 打平的决策里（slack=0，k=1），加权方案在13%–21% 的决策上换了候选，换的时候约八成 TNS 更低，代价是面积更大。整体上硬/软权重有 41.8% 的决策 TNS 变小，rootlevel 32.1%，不加权 15.3%。这是到目前为止最接近“加权有额外价值”的证据，但还没得到独立验证，也没有和面积代价、全局效果挂钩。
4. 面积总量变化、映射后延迟都没算。
5. **覆盖范围限制。** 只覆盖 ABC rewrite 会评估的恰好 4 个叶子的 cut，叶子不足 4 个的 cut（约 41.3% 的非平凡 cut）不在内；候选只来自 ABC 的子图库，不是所有可能的写法；选择只在每个 cut 内部比较，没有“每个节点的最终候选”。
6. 试点电路不具代表性（c1355 有 90% 的 root 零 slack）。电路扩到 44 个后仍然是探索性的，不能作统计结论。

## 必须知道的定义和坑

**基本定义**

1. **level**：从输入到该节点路径上的 AND 个数。PI 和常量为 0，AND 节点 = 1 + 两个输入的 level 最大值。D = 所有 PO 驱动节点 level 的最大值。
2. **required level**：PO 驱动节点为 D，其余节点 req\[n\] = min(各扇出 req − 1)。**slack = req − level**。
3. **cut 叶子的路径 slack**：`req[root] − (level[leaf] + 原结构里 leaf 到 root 的 AND 数)`。同一个 cut 里不同叶子的路径 slack 可以不同，这正是“有的是 WNS 路径，有的是短路径”的来源。
4. **MFFC**：严格、不重叠的划分。非根节点的扇出全部在区域内，所以时序只通过 root 出去，改写一个 cut 只会改变 root 的 level：`root_level = max(level[leaf] + 候选深度)`。
5. **目标函数 J = Σ w·depth**：不加权（w=1）、硬权重（cut 内最小 slack 的叶子权重 1，其余 0）、软权重 `exp(−(slack−m)/τ)`（m 为该 cut 最小 slack，τ=0.5/1/2，相对容差 1e-9）。
6. **本地 TNS 型指标**：a = level\[leaf\] + 候选深度，T\_k = req\[root\] − k（k=0..3），TNS\_k = Σ max(0, a − T\_k)，另外统计超过 T\_k 的叶子个数。

**导出字段和容易踩的坑**

1. **`leaf_depths` 的顺序按 `leaves` 数组下标，不按 `slot` 字段**，-1 表示这个叶子没用到。按 slot 取会悄悄错配。
2. **`nodes_added = −1` 表示自替换（保留原结构）**，按 0 处理。已知有 76 个“自替换但深度 +1”的情况，要注意别当成改写。
3. **`root_level` 是结构上的估计**：忽略节点共享，所以只是局部预测，不是安装后的真实 level。
4. **`rootlevel` 不是 ABC 命令**，是我们自己的选择规则（只最小化候选的 root\_level）。我查过 ABC 源码，没有这个命令。用户曾说它是 ABC 自带的指令，我还没得到他指的是哪条命令的答复，**需要向用户确认**。
5. **ABC 编号 = AIGER 里的 AND 编号 + PO 个数**，PI 编号不变。对不上编号就会整个错位。
6. **ABC 跳过扇出超过 1000 的高扇出节点**：cabac\_ucontext 里有 1 个（ABC 12381 ↔ step1 root 9211，required=−1）。
7. **ABC 默认 `rewrite` 已经是保 level 的**，`-l` 反而是把这个限制关掉；默认只保留每个 cut 里最好的一个候选；只评估恰好 4 个叶子的 cut。我自己早先写错过这一点（以为导出要避开 -l/-z）。
8. **评估口径的循环问题**：用 root\_level 降低率来比 rootlevel，它天然最优，因为这就是它直接优化的量。比较时必须用 TNS 型指标或全局指标，不能只看 root\_level。
9. **局部收益不可相加**：同一节点多个 cut、相邻改写互相重叠，局部降低不等于全局降低。
10. **覆盖范围**：41.3% 的非平凡 cut 不足 4 个叶子，不在候选里；候选只来自 ABC 的子图库。
