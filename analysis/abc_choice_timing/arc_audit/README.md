# 从映射网表解释 ID75 和 ID179 的组合错序

2026-11-18。在同一批冻结回放上，ID75 的初始与最终覆盖使用了不同的关键门链。ID179 在初始覆盖上只换计时方式就会改判，不同负载及其传给下一级的输入转换时间有可观测的逐弧差异。为测试一个便宜的替代办法，又在 12 个开发电路上运行了 ABC 自带的对数扇出惩罚。面积仅记录，所有选择均以时延为目标。

## ID75 的赢家为什么会变

两种改写的最迟路径都从 PI133 起始。最前面的门都是 NOR4xp25，D 引脚接 PI133，其余三脚分别接 PI130、131、132。用同一组 PI、PO 位置、网表引脚和中间网络对照后，得到以下实测。括号中的数字是逐门 Liberty 延迟，单位 ps。

| 阶段 | #6 | #8 |
|---|---|---|
| 初始覆盖，终点 PO92 | NOR4 (290.15) → AOI31 (97.16) → OAI21 (29.21) → A2O1A1I (11.56) | 相同门型与引脚顺序，分别为 275.15、94.20、28.72、11.48 |
| 最终覆盖，终点 PO90 | NOR4 (130.58) → NAND3 (89.66) → NAND2 (98.53) → OAI31 (27.63) → A2O1A1I (12.80) | NOR4 (115.26) → **NAND4 (126.56)** → NAND2 (120.21) → OAI31 (29.42) → A2O1A1I (13.22) |

初始阶段 #6 的 NOR4 扇出为 29，负载 14.62 fF，#8 分别为 28 和 13.83 fF。仅这一级 #6 就慢约 15.00 ps，整条路径慢 18.55 ps。最终阶段 #6 的第一级仍慢 15.32 ps，但其后两级分别快 36.90 和 21.68 ps，足以改变胜负，全路径快 45.46 ps。此处分解的是实际最长路径的时延差。某一项面积恢复决策如何改变全网其他单元的选择，尚需单独干预验证。[每级门名、命名连接、引脚、负载、转换时间及逐弧延迟](critical_arcs.csv)

## ID179 的首次可见差异

在两张各自固定的初始网表上，ABC 的 `print_delay po0006` 都从 PI2023 出发，显示 212.9 个固定引脚计时单位。在 #7 上该模型更看重 PO1035（227.4）；全局 mode0 因而把 #7 排在 #1 后面。改用 Liberty 后，两者最慢路径都变成 **PI2101 → PO6**，两条路径的 11 个门型、引脚、跳变方向均一致。沿这条 Liberty 路径累加对应 GENLIB 引脚延迟，两者同为 200.85。这是对指定路径的求和，与上述端点最迟值分开报告。

| 初始关键路径上的位置 | #1 | #7 | 同一位置的观察 |
|---|---:|---:|---|
| 第一级 XOR2.B | 213.094 ps | 213.094 ps | 两者的该级负载相同 |
| 第二级 NOR2.A | 2537.58 ps | 2532.06 ps | 首个有差异的弧，扇出 449／448，负载 161.86／161.50 fF；输入 slew 同为 408.64 ps |
| 第三级 NAND4.A | 1218.63 ps | 1216.19 ps | 负载相同，上一级传来的 slew 为 5349.02／5337.11 ps |
| 第十级 A2O1A1O1I.A1 | 5068.90 ps | 5061.26 ps | 扇出 1024／1023；同一 #7 引脚的 Liberty 表在 20 ps、1 fF 下给出 28.98 ps，只换成实际负载 351.46 fF 后为 5066.55 ps |

第九级反向抵消约 4.01 ps，整条初始路径 #7 快 12.10 ps。两种最终覆盖的最慢路径均为 PI2094 → PO3。第三级虽然同为 NAND2xp33，选入关键路径的引脚分别为 B 和 A，扇出为 216 和 32，负载 75.94 和 9.37 fF；两条弧分别为 1176.47 和 247.36 ps。该位置相差 929.10 ps，整条路径相差 929.12 ps。两端其余级也发生了上百 ps 的正负变化；单独替换第三级的因果收益尚未测量。

ID179 多个实际负载、slew 超出了 ASAP7 相应表的采样上界。例如第十级负载 351.46 fF，表上界 11.52 fF。上述数字严格对应项目指定的 ABC Liberty 插值／外推实现；大扇出情况下的物理时序精度需要额外依据。逐弧文件同时给出用 20 ps 和 1 fF 作固定参考、仅改变负载、仅改变 slew 的同表查询；这些是固定弧的数值敏感性，不是全网重新计时。[逐弧数据](critical_arcs.csv)

## 12 个开发电路的反证与对照

每个电路在原先冻结的 8 个非空组合中择一，使用相同的 CEC 通过标签。并列先取编辑少、再取组合号小者。Regret 是相对该电路 8 个组合中最快实测值慢多少百分比，随后按电路等权平均。开发集用于诊断。下表两组各有自己的原生基线。

| 评分方式 | 最优命中 | 平均 regret |
|---|---:|---:|
| 逐组合单独安装、ABC 初始 mode0 | 2/12 | 3.045% |
| 同一组合先生成初始覆盖，再用 Liberty 计时 | 4/12 | 2.516% |
| 用 LiteCut 修正 pin 匹配后生成初始覆盖，再用 Liberty 计时 | 4/12 | 2.709% |
| 一次准备候选 cut，ABC 条件传播 | 1/12 | 3.087% |
| 同一候选集加 ABC 对数扇出修正 | 4/12 | 2.970% |
| 对数扇出修正再加 LiteCut | 4/12 | 2.970% |

前三行是离线对照，每个组合需要独立生成网表。Liberty 选中了 ID179 的 #7，但在 ID75 选了 #8。去掉 ID179，余下 11 例的平均 regret 从初始 mode0 的 1.911% 升到初始覆盖 Liberty 的 2.745%。本面板不能支持简单替换整个评分器。

后三行直接在原图及候选共同准备的 cut 上传播，不对各组合生成完整映射。预先固定 `map -F 100`，约等于每当 AIG 扇出翻倍，增加一级反相器的标称延迟。LiteCut 使用上轮冻结的 α=0.5。扇出修正使 ID58、421、770 改选到各自最快组合，其他 9 例选择相同；LiteCut 未再改变任一选择。ID75 的 6、8 依然打平；ID179 的 7、1 为 273.248、264.468，仍反向。共同图的 AIG 扇出只有节点数，实际负载取决于哪些门最终被选中，以及各接收引脚的电容。[全组合评分](scores.csv) · [逐电路选择及真实延迟](choices.csv) · [汇总](summary.csv)

## 核验与决策

冻结 AIG 逐文件核验 SHA-256，无改写最终映射流程的变更。逐条件原生分数与归档比较，未加扇出项的 108 个状态（含 12 个空组合）均复现基线。ID44 的 #1/#7 作为对照，同样检查两种覆盖。新 observer 对 ABC 的 Liberty 表做只读查询，每条回溯路径逐段重构到达时间。交付表的 12 条最长路径、90 级门与写出的 Verilog 按命名引脚逐段对上，终点、起点和逐弧和均经脚本检查。编号只在各自的映射网表内使用。[运行索引](RUNS.json)

本轮保留扇出项作为便宜的实验基线。下一版代理值得验证的具体量是**候选覆盖选中的接收门及其输入电容**。可以先从受改写影响的门和相邻扇出开始，估算负载并向后传播 slew，再查本地库表。首先检验能否重现 ID75 最终第二、三级的相对时延和 ID179 的最慢输出；通过后再接入 GPU 联合梯度搜索。两个冻结反例均未被现有廉价修正解决，所以本轮没有扩大独立评测。
