## 损失审查与失败归因

训练前审查确实发现拟合与排序冲突：旧checkpoint上，33个非零排序梯度的训练项中，
16项的数值拟合梯度与新排序梯度反向；拟合/旧排序梯度范数比中位数47.03。
这只说明存在局部目标冲突，不证明替换损失就能改善选优。
完整公式、单变量控制与冻结顺序见[方案和审查](PLAN_AND_AUDIT.md)、[协议](PROTOCOL.json)。

三个种子均训练21轮，按原patience20停止，最佳checkpoint都是epoch0，即完成首轮更新后。
规则事前固定为最小开发损失；本轮随目标一起替换该损失，没有事后挑选epoch。
后续训练损失下降而开发损失上升。按**同一个新目标**重新评价旧/新输出，旧checkpoint
在三个种子的开发损失也都更低（[同目标核对](postmortem/same_objective.csv)）。
因此不能把新训练的数值下降说成相对旧模型的目标或选优进步。

新模型85个开发严重反向对中，54个在固定时序传播中已反向，31个原本预测并列。
证据见[逐对来源](postmortem/severe_reversal_origins.csv)。这说明残差没有可靠纠正
基础传播的错序/不可区分性；仅凭这些结果不能确定是输入缺乏辨识信息、共享残差容量、
传播结构或训练泛化中的哪一个导致失败，也不能据此归因于LiteCut本身。
固定传播比较使用同批组合的历史记录，不替代真实Mapping标签。

训练集成对准确率41.12%→49.03%，但平均Regret也从2.100%升到2.522%。
成对目标对所有配对分配梯度，并不直接保证Top-1；本轮同时存在开发泛化失败和
训练域选优未改善，不能简单认定为“训练损失完全没有作用”或“只需增加训练轮数”。
GPU/CPU梯度、有限差分及错误排序梯度方向检查通过，未发现本次损失的符号或数值错误。

下一阶段仍建议先检查原特征和传播能否区分关键的错序组合，以及残差能否改变这些
组合的相对输出；再依据证据决定表示或传播修改。本轮不再尝试损失权重、训练轮数
或更大网络，也不推进独立Mapping评估和联合梯度优化。
