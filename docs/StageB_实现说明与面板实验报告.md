## 一、我们具体实现了什么？（代码架构一览）

我们在 **零破坏保留 Stage A（`rw4b -r 3` 默认入口）** 的前提下，以独立 CLI 开关 `--joint-grad`（默认 `--steps 25 --lr 0.20 --disc-lam 0.30 --tns-rho 0.85`）接入了完整的 Stage B 引擎，核心代码拆分为两个清晰模块：

1. **外层区域划分、帕累托菜单与回装（`projects/culs/src/algorithms/rw4b.cu`）**：
   - **GPU 分层预筛与 4 槽位帕累托菜单核函数**（`evaluateNode4BMenuKernel`）：复用 Stage A 的 12 槽位混合 4-cut 与完整锥 `coneIds` 评估，按物理可达性分层预筛（近临界/TNS 视野内放宽保留提速候选；视野外仅保留 `da <= 0` 且不恶化局部锥延迟的候选），同时执行 `slack_other` 扇出安全护栏与 `level(hit) < level(root)` 严格层序约束，为每个节点产出最多 4 种互补候选（纯速 / ADP 均衡 / 省门 / 低扇出）。
   - **线性复杂度 GWMIN 无冲突选区**：统计冲突度 $d(m)$，按全局归一化 ADP 权重 $W(m)/(1+d(m))$ 选出满足 4 条硬性不变式的活跃区域集 $\{R_1, \dots, R_M\}$（`remAll` 互不相交、`remStrict` 与所有候选 `leaves`/`hitIds` 双向互斥、`level(hit) < level(r_m)`、被下游引用的活跃根剔除导线折叠候选）。
   - **紧凑微子图与稀疏外部扇出 CSR 打包**：把每个候选编码为最多 12 个内部 2 输入门（`SubGate`），`k=0` (`no-op`) 统一编码为读取原图 `(f0[r], f1[r])` 的 1 门微子图；稀疏 CSR 表仅记录区域外部存活节点（`leaves` 与 `hitIds`）的扇出净变化，杜绝 `remStrict` 内部门自污染。
   - **离散回装**：沿用 Stage A 验证零崩溃的 `StrashRebuild (--fo-cap 0)` + PO 可达性剪枝，确保与 ABC `read_aiger` 自动 strash 语义 100% 对齐。

2. **内层全 GPU 双通路可微优化器（`projects/culs/src/algorithms/rw4b_grad.h` & `rw4b_grad.cu`）**：
   - **6 个全 GPU 核函数流水线**：
     1. `k_softmax_and_exp_fo`：Softmax 概率映射 + 稀疏 CSR 汇总期望扇出 `d_expFo`（PI 存负相位扇出 `negFo` 对齐 `pi_phase_aware`）；
     2. `k_fwd_level`：按拓扑层 `1..L` 实时推进光滑 `SoftPlus(tau_fo=0.1)` 负载与微子图 LSE+Slew 前向，缓存分支权重；
     3. `k_po_loss_stats` / `k_aux_loss_terms` / `k_po_grad_init`：以 `fp64` 归约无量纲多目标 Loss（近临界 PO 归一化的 TNS + WNS + 面积 + 按 $|V_0|$ 归一的 Gini 磁铁），初始化 PO 伴随梯度；
     4. `k_bwd_level`：逆拓扑层 `L..1` 精确反传到达时间与 Slew 伴随梯度（通路 1），含负相 PI 累加器；
     5. `k_fanout_grad`：一次性并行算出三类节点（普通门 / 活跃根概率加权 / 主输入负相边）精确期望扇出偏导 `d_gFo`（通路 2）；
     6. `k_region_grad_and_adam`：读取 CSR 汇总扇出投诉，合成完整 4 项概率梯度，在 `fp64` 中过 Softmax Jacobian 并用限幅 Adam 更新 `d_logits`。
   - **硬门槛 1：双精度中心有限差分校验（`--grad-check`）**：将 GPU `fp32` 解析反向梯度与 `fp64`（$\epsilon = 10^{-6}$）中心差分逐项比对，在 `c1355_orig`、`c5315_orig`、`intra_pred_PE` 上全部达到 **$10^{-8}$ 级别绝对误差（`PASS < 1e-4`）**，证明双通路求导实现零 Bug。
   - **GPU 多置信度阈值离散寻优 + 置信度降序扇出堆叠守卫**：内层 25 步结束后，在 GPU 上对 8 档阈值 $\theta \in \{0.35, 0.50, 0.65, 0.75, 0.85, 0.92, 0.96, 0.985\}$ 跑精确硬 `max` 离散前向（合计约 1~3 ms）选出离散 ADP 最优档，并在回装前按梯度置信度降序执行 1 遍实时扇出堆叠检查，彻底消除多区域同时堆叠到同一非关键网线引发的 ASAP7 Slew 悬崖。

## 二、从首版 MVP 到全面超越 Stage A：我们排除了哪 4 个核心问题？

Stage B-1 并非一次蒙对超参，而是通过 4 轮严谨的 Slurm 消融与日志诊断，逐个打掉了 4 个真实的物理/动力学问题：

| 迭代轮次（Slurm Job） | 发现的根因 | 采取的修复 | 16 电路面板 Delay / Area / ADP |
|---|---|---|---|
| **1. 首版 MVP（`66406`）** | 梯度校验一次性达到 $10^{-8}$ 精度，但：① 菜单放进了未加 `deltaJ>=0` 与 `slack_other` 保护的 `da<0` 候选；② 初始 `lr=0.25` 过早饱和（`avgMaxP=0.998`）；③ `sram_64`/`dmem` 退回原图 | —（首版基线） | `-30.91%` / `-5.54%` / `-34.74%` (`10/16`) |
| **2. 菜单安全护栏 + 阻尼 Adam（`66409`）** | 抓出 **GWMIN 排序权重 Bug**：排序时加了未归一化的 `1e-4 * bestDj`，大电路上比全局 `bestAdp (~1e-5)` 大几十倍，导致非关键区把关键路径 MFFC 挤出独立集；且高 `eps` 冻住了 95% 区域 | GWMIN 严格按归一化 `bestAdp` 排序；恢复标准 Adam `eps=1e-8` | `-18.79%` → 修后 `66410` `-25.22%`（`BMD_EP_MEM`、`c1355` 等立刻解锁） |
| **3. 诊断 `dmem` / `sram_64`（`66412` & `66414`）** | `srun` 抓出两大物理爆炸：① 二次 `lamFo*(fo-6)^2` 在 4000 扇出内存线上炸到 `115.0` 淹没 WNS/TNS；② **`t=1` 均匀初始化（$p(\text{改写})\approx 0.75$）让 4~5 万个区域同时开启，共享网线扇出瞬间叠加把 `initLoss` 轰炸到 `114.85`（57 倍于 $D_0$）** | ① 令 `lamFo = 0`（完全交由通路 2 精确物理扇出/Slew 梯度）；② 改为贴近原图初始化 `z_{m,0} = 2.5` + 过滤低收益噪声区 | 跃升至 **`-38.01%` / `-2.17%` / `-39.36%`**（7/16 反超 Stage A，`sram_64` 解锁至 `13.3k ps`） |
| **4. 消除单点扇出堆叠悬崖（`66415`）** | `66414` 中仅 `reservation_station` 单张电路因数百个非关键区同步堆叠到同一网线，触发 ASAP7 Slew 悬崖暴涨到 `64,895 ps`（拖低整盘 13%） | 离散化后增加按梯度置信度降序的实时 `accFo + slack_other` 扇出堆叠守卫 | **`-47.00%` / `-3.13%` / `-48.66%`（`14/16` 胜原图，全面超越 Stage A！）** |
