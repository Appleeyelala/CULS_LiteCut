## 一、我们的终极研究目标是什么？

本项目面向大规模逻辑综合（AIG Rewrite），聚焦两个核心创新方向：

1. **多目标、多路径的端到端全局梯度联合优化（最高优先级）**：
   - 真实电路中 PI→PO 路径数量是指数级的，不能只盯一条最慢路径，而要**同时兼顾多条关键与近临界 PI→PO 路径**，并在**扇出负载、Slew 传播与面积（ADP）**之间全局权衡。
   - 目标是在 **GPU 上对多个 MFFC 区域的候选替换做多步端到端可微梯度联合优化**，使最终经过 ABC Technology Mapping（ASAP7 工艺库）后的**真实全局 Critical Delay 与 ADP** 尽可能降低。
2. **GPU 并行加速（核心工程与系统创新点）**：
   - 将候选生成、全局时序正反向传播、多步梯度优化等主要计算阶段原生实现在 GPU（CUDA）上，实现百倍级加速并严守 **100% 功能等价（`cec -n`）**。

## 三、Stage A 究竟做了哪些关键改动？（核心原理拆解）

为了把 GPU `rw4b` 从最初的 `-3.19%`（且一度面积膨胀到 `+8.16%`）打磨到最终的 **`Delay -10.22% / Area +3.73% / ADP -6.88% / 313.9×`**，我们先后落地了 **6 大核心改动**：

### 改动 1：12 槽位“分层混合” 4-Cut 枚举（解决候选池看不到提速结构）
- **原问题**：CULS 原生 4-cut 枚举只保留 8 个“面积/共享度最小”的 cut，导致高扇出关键路径上的提速 cut 被系统性挤掉；且原淘汰逻辑会先踢 3–4 叶子紧凑 cut。
- **改动**：
  - 将每节点 cut 槽位升级为 **12 槽位分层混合**：`1 个平凡 cut + 5 个时序优先槽位（按 maxArr / sumArr 排序）+ 6 个面积/共享度优先槽位`；
  - 修正面积槽位驱逐优先级（先淘汰 `nLeaves < 2` 和 `== 2` 的小 cut，保护 3–4 叶子省面积 cut）。
- **效果**：同时保留了降延迟候选与省面积候选。

### 改动 2：分离“完整 4-Cut 内部锥 `coneIds`”与“严格 MFFC `remIds`”（打通高扇出绕行）
- **原问题**：此前在算局部叶子延迟 `leafDelays` 和原始代价 `jOrig` 时，只遍历了严格 MFFC（`remIds`），漏掉了锥内但被外部共享的内部节点。一旦关键路径经过高扇出共享节点，GPU 会以为原锥延迟很短，从而漏掉大量真正能绕开高扇出瓶颈的改写。
- **改动**：
  - 明确分离两个集合：`remIds`（严格 MFFC）只用来算**能省掉的门数 `saved`、`origRefs` 和 `slack_other` 排除集**；`coneIds`（从 root 到 4 个叶子的完整内部锥）专门用来精确反传 **`leafDelays`、`jOrig` 和 `leafLocalSens`**。
- **效果**：单这一项就让 GPU `--v1` 在全集 905 电路上从 `+4.56%` 跃升至 `-2.75%`，高扇出电路（如 `FFTStoreBit`、`sram_64`）被彻底打开。

### 改动 3：修复 GPU MFFC 记账越界 Bug（Claude P0-4）
- **原问题**：GPU 核函数做 MFFC BFS 时，把“尚未归零的暂定共享节点”和“已确认可删的 `remIds`”共用了同一块数组。一旦有节点引用计数归零写进 `remIds[remCnt++]`，就会覆盖暂定区第 0 项并让整个偏移错位，导致 `saved` 和 `da` 失真，误选大量虚增面积的改写。
- **改动**：拆分为独立的 `trkIds[]` / `trkRem[]` 局部数组，彻底消除内存覆盖。

### 改动 4：对齐选块评估与拓扑重建口径（Claude P0-1）
- **原问题**：选块阶段以为复用了某个已有节点（0 新增门），但重建阶段存在三处不一致：
  1. 未跳过已选改写删掉的 `remStrict` 死节点，它们在重建时先给叶子和命中节点虚增了扇出；
  2. 命中复用节点 `hitIds` 在选块冲突检查中没受保护，可能被另一个选中的改写删掉；
  3. 重建展开子图时没有在评估期命中的 `match[j]` 处停下，反而一路展开到叶子，引发级联多建门。
- **改动**：重建直接跳过 `delStrict[id]`；每个选中项记录 `hitIds` 与 `match[54]`，冲突检查双向保护 `hitIds`，重建遇到 `op.match[j] != -1` 时直接复用 `litMap[match]` 不再展开。

### 改动 5：规模无关 ADP 一阶打分 + 近关键 `da > 0` 硬门控（Claude P0-3 & P0-2）
- **原问题**：
  1. 原打分 `effDelta - 0.05 * da` 的量纲随电路 PO 数量膨胀：敏感度总和 $\Phi = \sum_{\text{po}} \exp((a_{\text{po}} - D)/\tau)$ 在大电路（OpenABC/ACE）上很大，固定的 `0.05` 根本挡不住加门，导致面积膨胀到 `+8.16%`（OpenABC/ACE 高达 `+13.6%`）；
  2. 原 `--fo-cap 16` 不分关键/非关键允许复制重复门，但我们直接用冻结的 ABC 实测证实：**ABC `read_aiger` 会自动 strash 合并结构完全相同的重复 AND 门**。
- **改动**：
  - 在 GPU `initSensPOKernel` 中实时累加全局归一化因子 $\Phi$；
  - 将打分升级为与电路规模完全无关的 **ADP 一阶泰勒判据**：
    $$\text{score} = w \cdot \frac{(s_{\text{root}} / \Phi)\cdot \Delta J - (\text{side} + \text{slewCost})/\Phi}{D} - \frac{\text{reg}}{D} - \frac{da}{A}$$
    其中 $D$ 为当前代理深度、$A$ 为当前 AND 门数，并同步对齐 Host 惰性重排的 `extraReg` 量纲与 `1e-9` 阈值；
  - 增加近关键硬门控：所有增面积改写（`da > 0`）仅允许 `slack(root) <= kappa * tau` 的近关键节点执行；
  - 在 16 电路面板扫描 `(w, kappa)` 确定最优组合 `w = 2.0, kappa = 2.0`，并在全量 905 电路实测证实关闭重复门（`--fo-cap 0`）全面优于 `--fo-cap 16`（Delay `-10.22%` vs `-8.58%`，ADP `-6.88%` vs `-5.15%`）。

### 改动 6：其余精度与工程修复（Claude P1-1 ~ P1-4 + 系统稳定性）
- **P1-1**：叶子 `slack_other` 预算查询改传 `remIds`/`remAll`（不再误排除锥内共享消费者）；
- **P1-2**：补齐 `rt < 4` 直连 PI 候选的负相位扇出记账；
- **P1-3**：对低扇出安全增量（`newCnt <= pivot && dd <= 0.5`）豁免 `slack_other` 硬拦截；
- **系统稳健性与提速**：过滤 float32 零增益抖动（`da == 0 && effDelta <= 1e-5`）、强制所有 AND 门 `lit0 <= lit1` + DFS 后序规范化（彻底消除 AIGER 写出崩溃，实现 **905/905 零崩溃**）、将 Host 重建查找表 `chosenIdx` 从 `unordered_map` 改为 `vector<int>`。

## 四、当前现状评估与下一步：进入 Stage B

### 为什么 Stage A 已经具备很强的论文底座，但仍需要 Stage B？
- **Stage A 的成就**：我们已经证明了“多路径扇出+Slew 可微时序代理 + 规模无关 ADP 一阶打分 + 原生 CUDA 并行引擎”的威力（全集 Delay `-10.22%`、ADP `-6.88%`、`313.9×` 加速）。
- **与终极目标的唯一核心差距**：Stage A 每轮本质上还是**“单步一阶敏感度打分 + Host 串行贪心选点”**——它在给每个 MFFC 打分时，假设其他 MFFC 都不动，无法在一次决策中显式协同**上下游多个 MFFC 同时修改带来的非线性路径竞争与扇出重排**；且 Host 端串行选点+重建仍占端到端耗时的主要部分。

### Stage B 总体计划（GPU 端到端多 MFFC 梯度联合优化）
1. **多 MFFC 连续松弛**：在全图选取一批互不冲突的 MFFC 区域 $\{R_1, \dots, R_M\}$，为每个区域的 $K_m$ 个合法候选（含保持原样）引入连续 logits $\theta_m$，通过温度退火 Softmax / Gumbel-Softmax / STE 映射为选择概率 $p_m$。
2. **多路径多目标全局损失**：在 GPU 上联合优化
   $$\mathcal{L}(\theta) = \underbrace{\text{LSE}_{\tau}\!\left(\{a_{\text{po}}(\theta)\}\right)}_{\text{多条关键 PI}\to\text{PO 路径}} + \lambda_{\text{TNS}} \sum_{\text{po}} \text{SoftPlus}(a_{\text{po}}(\theta) - T_{\text{target}}) + \lambda_{\text{area}} \cdot \frac{\mathbb{E}[\Delta A]}{A}$$
   直接复用 Stage A 已经跑通的毫秒级 CUDA 按层前向/反向核函数，在 GPU 上做 $T$ 步（如 20~50 步）联合梯度下降，将上下游耦合与多目标权衡一次联合求解，最后离散化回装并做 `cec` 等价验证。
3. **最终论文收官**：在全量 905 电路上完成 Stage A vs Stage B 消融对比（单步一阶贪心 vs 多步 GPU 梯度联合优化），所有超参锁定后，在严格封存的 **24 电路外部盲测集（`panel.json`）** 上做一次性最终验证。
