# 全局代理与多 MFFC 联合梯度研究实施契约

本目录实现用户批准的分阶段计划，所有结论以新运行证据为准。

1. **阶段0**：核对非正 Gain 905 的真实记录，按统一容差区分平滑目标、预测 Critical Delay 与真实 Delay；冻结按家族/重复输入分组的训练、验证、测试划分。
2. **阶段1**：12个开发电路，三个机制层各4个；每例最多4个兼容Decision、跨至少2个MFFC，最多16个子集。所有请求和预测在读取新候选标签前冻结。完整安装、CEC和真实Mapping独立执行。组合oracle只用于诊断，不作为部署方法。
3. **阶段2**：分别实现目标对齐、可组合多端口代理、约束联合梯度；以旧代理/新代理与旧STE/新选择的消融隔离作用。仅在机制证据需要时离线拟合共享参数，LiteCut冻结。
4. **阶段3**：独立24例验证、预算曲线；检查电路内排序、方向精度、代理搜索差距、真实Delay、面积和失败。门槛见配置；未通过不扩大实验。
5. **阶段4**：冻结后留出100例，满足相对B的Delay几何均值≤0.99、家族bootstrap上界<1、相对A<1、CEC及面积合规，才扩大到905。全905拟合采用家族交叉拟合；开发数据不能称盲测。

部署仅一次原图Mapping；最终候选Mapping属于独立验证，禁止用于改选、回退、重启。所有Runtime同时记录完整实测、第二次ABC命令和研究记账值。研究计时不冒充一次Mapping部署实测。

当前905源码为`bd87a176...`，执行修复起点为`ee1ccc53...`。旧STE100和历史方向导数905不混算。代码通过新模块/协议引入，不修改历史固定参数入口。MFFC、Decision、cut-bounded rewrite region和candidate身份保持独立。

每阶段记录源码commit、输入/工具/模型hash、Slurm资源、命令、输出和未通过项。全部重计算在`/data/wushangge`通过Slurm；单作业内顺序使用GPU。历史数据只读。磁盘空间不足时保留已经完成的产物，暂停新增大规模输出，不删除历史证据。

公开小型交付：协议、分组清单、证据表、组合诊断、实现说明、消融与门槛结果；完整AIG、模型、库和日志留在数据区。
