# Step 3 v3：(A) 近临界路径指标，(B) 扩展到 45 个电路

## 范围与前提

- 只覆盖 ABC rewrite 会评估的**恰好 4 个叶子**的 cut；选择只在每个 cut 内部，不比较不同 cut，也不产出
  “每个节点的最终候选”。
- **局部 root_level 降低不等于全局 level 降低**：全局要所有最长路径同时变短，只有联合安装后才能验证。
  本步骤没有安装候选、没有重传播 level、没有做映射，因此不下“全局变快”的结论。
- (A) 不需要重新导出：直接用第 2 步的导出与 v2 的七套选择规则；(B) 只对新增电路导出；(C) 见
  `analysis/level_weighted/abc_native/`，只是全局基线，不进入这里的比较。

## (A) 指标定义

对每个被选中的候选，取它用到的叶子（`leaf_depths ≥ 0`）：

| 量 | 定义 |
|---|---|
| `a_l` | `level[l] + leaf_depths[l]`（候选）；原结构用 `level[l] + d_orig(l)` |
| `T_k` | `required[node] − k`，k = 0,1,2,3 |
| `TNS_k` | `Σ_l max(0, a_l − T_k)` |
| `N_k` | `a_l > T_k` 的叶子路径条数 |

`k = 0` 时 `T = required[node]`：合法候选的 `a_l ≤ root_level`，所以原结构恒为 0，候选只有越过 required
才会非零；这个记号主要用于捕捉越界。`k ≥ 1` 才是压近临界路径的主指标。

软权重继续用 v2 的平移写法 `exp(-(slack−m)/τ)` 与相对容差 `1e-9·max(1,|J|)`；不加权/硬权重/rootlevel/
abc_default 的目标是整数，精确比较。

外部 24 个考试集**没有被读取**：代码在打开任何路径之前，先用 SHA-256 集合与名称族双重排除，并记录
命中情况——`cohort.json` 的 `excluded_panel` 显示 24 个 SHA 与队列的已知集合交集为
**0**，名称族交集为空。

新增电路共 41 个（开发 11 + 抽样 30），逐个重跑第 2 步的六项验收与第 3 步断言：`check3` 增益不一致 0、

1. **100–299 档为空、300–999 档只有 4 个**：905 里没有更小的组合电路（最小 403 AND）。按规则登记，
   并用 ≥1000 档的哈希序补齐到 30 个，逐条在 `cohort.json` 里标 `substitute=true`。
2. **新增电路包含 2 个 >100,000 AND 的开发电路**（b18 109,594、jpeg 114,771）：`>100k 跳过`只适用于
   905 抽样，开发 14 个按原计划全部导出。
3. 没有安装候选、没有 level 重传播、没有映射、没有联合替换、没有启动子代理。
