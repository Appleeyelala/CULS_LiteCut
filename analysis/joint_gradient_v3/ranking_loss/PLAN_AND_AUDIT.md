# 排序损失单变量方案与训练前审查

本轮仅检验一个损失设计，基准是原始v3仅全局残差。上一轮endpoint-context
代码和结果保留在仓库，但本实验明确禁止启用它。协议在拟合前提交于
`f7b348b3`；[PROTOCOL.json](PROTOCOL.json)固定公式、种子、并列规则与停止条件。

## 原损失的具体冲突

旧损失为PO数值Huber＋Critical数值Huber＋0.1成对logistic，后者还插入
原图零参考。原图/serialized no-op混杂并不会因这种原图配对而消失。
此前15/33冲突计数针对非加权非空组合排序与旧总损失；本次进一步拆出
**纯数值拟合梯度**，与新定义的差距加权排序梯度比较，不混用两次口径。

Slurm66055在三个原checkpoint上完成只读检查，96组合原预测逐项重现，
误差均为0ps。训练36个电路×种子中，ID246三个种子的组合真实Delay全并列，
排序梯度为0；其余33项中，**16项的数值拟合梯度与新排序梯度方向相反**。
数值拟合项/旧0.1排序项的参数梯度范数比中位数为**47.03**。

| 种子 | 训练电路中拟合与新排序梯度反向的ID | 等权训练汇总梯度余弦 |
|---|---|---:|
| 20261117 | 81、6、688、3、85、25 | +0.4979 |
| 20261118 | 6、338、688、3、85、25 | −0.6271 |

开发集36项中11项的拟合梯度与新排序梯度反向。它们只是旧checkpoint处的
局部梯度，不能证明整个训练轨迹一直冲突；汇总梯度也只有一个种子反向。
这支持检验“拟合主导目标是否妨碍选优”，不证明所有错误都由损失导致。
例如正确排序的组合仍可能因为logistic继续扩大间距而与数值回归冲突。
逐项证据见 [audit/gradient_components.csv](audit/gradient_components.csv)。

## 唯一改动

取组合预测/真实PO到达的最大值为p/y，保持单位ps。令s=原图Delay×1%，
对于真实可区分的同电路、同候选域组合对：

`w = min(|y_i−y_j|/s, 1)`

`L = mean(w · softplus(−sign(y_i−y_j) · (p_i−p_j)/s))`

不保留绝对回归项、不引入混合权重、不加入原图零参考、不跨域拼标签。
采用稳定softplus、权重上限1和原有梯度范数裁剪5；近似并列权重较小，
不再用权重和归一化把它们放大。真实并列按已有0.001ps最小锚点分组，
预测并列不能被过滤，因为它需要学习梯度。

旧历史域每电路仅1个组合，仍加载和记录，但没有配对，损失为可微零；
原来的按域样本数加权保留，因此8组合域的贡献系数仍为8/9。这是损失
从数值监督转为配对监督的直接后果，不是删除坏样本。12个原训练电路均保留。

## 固定执行顺序

1. 完成梯度分解和损失测试，再开始拟合。
2. 在原v3结构、原特征上训练20261117/18/19；AdamW、学习率、权重衰减、
   初始化和打乱规则、200轮上限、patience20及改善阈值1e-6全部保持原设置。
3. checkpoint仍按最小开发损失选择，但使用本轮同一个排序损失；此规则
   预先冻结，不事后改成Top-1、最佳种子或其他epoch。基准checkpoint保持原样。
4. 复用上轮评估脚本的数学函数，对原12开发电路各8组合配对比较。
   同时报告训练集指标帮助辨别欠拟合与开发表现，不将其当作泛化成绩。
5. 三种子均改善Pairwise、整体Top-1不下降、各种子平均Regret不升且汇总下降、
   最差Regret和严重反向对不增加、没有新增跨过5% Regret的电路×种子，
   才建议下一轮独立确认。此为工程决策规则，不是显著性检验。

测试中，原损失对统一标签偏移的“不变性”断言按预期失败，新损失通过。
这验证的是新目标所需的性质，不把旧回归目标称为实现bug。7项新损失测试、
6项原代理测试、7项排序测试全部通过，包括CPU/GPU、有限差分、空配对、
真实/预测并列、权重饱和与极端数值稳定性。证据在Slurm66055日志。

本轮没有新Mapping、新数据、额外网络或搜索器运行；原测量输入规范与
serialized no-op限制不变。12电路反复用于开发，不是独立测试集。
