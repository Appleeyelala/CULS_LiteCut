# ABC 驱动的跨 MFFC 改写选优实验

2026-11-18。冻结面板表明，直接用 ABC 初始延迟匹配给组合排序，会漏掉最终 Liberty 时序的大差异。按 LiteCut 局部比值校准 pin 时延在训练集有效，进入开发集后平均选优损失上升。研究入口默认使用原生 ABC pin 弧（α=0）。独立推广和端到端加速仍待验证。

## 实现及评价对象

| 环节 | 实际工作和成本 |
|---|---|
| 离线 full choices 参照 | 将保持布尔函数的候选接到 ABC choice 类上，记录实际覆盖用到的 cut、相位、supergate 和兼容组合。先冻结选择，再 CEC 并用冻结工具核验可回放的 AIG。覆盖本身的 Liberty 时序和组合回放后的 Liberty 时序分别记录。 |
| 有／无 LiteCut 消融 | 在同一个已安装 AIG 上对 ABC 的引脚时序弧缩放。倍率为（候选局部预测／原局部预测）的 α 次方，保留 pin、相位和 rise/fall 差别；对应关系不唯一或比例无效时使用原生弧。多个序列化节点对应同一带符号 ABC literal 时由 ABC 校验。采用 AiMap 的局部校正思路，比例来自现有冻结 Student。 |
| 一次准备、多次打分 | 原图一次完整 map 提供稳定边界的正反相 rise/fall 到达时间。ABC 用共同 choice 图枚举受影响的 cut、supergate 和 pin 弧，在全局覆盖前导出。CPU/CUDA 在图上沿 pin 传播，按同一 supergate 的最慢跳变选择实现，最后取最慢 PO。联合梯度用连续松弛反传；实际提交的组合通过硬约束投影。 |
| 最终验收 | 只有选出非空组合才实际安装并调用冻结 ABC 做位置对应 CEC、map 和 Liberty `stime`。全部编辑安装成功、CEC 通过、面积 ≤ 原图 1.05 倍且延迟严格改善时返回该 AIG。结果记录返回文件及哈希。空组合直接返回原 AIG。 |

稀疏原型每个 root 的「保留／各改写」共用一个分类变量，跨 root 独立编码，并在投影时检查 MFFC 冲突和候选复用。位掩码当前最多容纳跨 root 合计 64 个局部状态（包括各自的保留状态）。入口使用准备好的 catalogue、owners 与 Student scores。全 choices 覆盖和逐组合 native map 都是离线参照，搜索入口不逐组合运行 ABC。

## 两个错序最早出现的位置

旧 v3 记录中，ID75 的 6/8 和 ID179 的 7/1 两对在固定传播输出就已经错序，三个种子的排序残差也未纠正。下面在同一批冻结 AIG 上进一步拆开 ABC 自身的三个阶段。mode0 是 ABC 内部匹配分数，后两列是库、AIG 一致的 Liberty 实测。前者使用 `map -r` 的初始覆盖，后者使用常规 `map` 面积恢复后的覆盖。

| 电路、固定组合 | 初始 mode0 | 初始覆盖 Liberty，ps | 面积恢复后 Liberty，ps |
|---|---:|---:|---:|
| 75 #6 | 88.020 | 428.085，PO92 | **359.195**，PO90 |
| 75 #8 | 88.020 | **409.540**，PO92 | 404.658，PO90 |
| 179 #7 | 227.430 | **9553.551**，PO6 | **5987.977**，PO3 |
| 179 #1 | **216.420** | 9565.653，PO6 | 6917.100，PO3 |

ID75 在 mode0 打平。用 Liberty 测初始覆盖时 #6 更慢 18.546 ps；面积恢复后 #6 反快 45.463 ps。即使用精确 Liberty 测初始覆盖，这对组合仍会选反。ID179 在 mode0 已将 #7 排在 #1 后面；改用 Liberty 测初始覆盖时方向纠正，#7 快 12.103 ps；最终真实优势扩大到 929.123 ps。此处观测到的是计时口径和实际单元覆盖变化所处的阶段。要归因到某个单元替换、pin 负载或输入 slew 对排序翻转的贡献，还缺跨覆盖的关键路径与逐弧分解。

## 完整 choice 覆盖与可部署改写

12 个析因电路各含 4 个兼容二选一决策，实际有 191/192 个完整真实延迟。每例使用同输入历史 Baseline B。以 CEC 通过且面积合格的已测组合为范围，事后逐电路最优／B 的几何比为 **0.915916**，其中 9/12 快于 B。这里的最优只在固定候选面板内成立。

原生、α=0.5 和 α=1 的完整 choice 覆盖共 36 个，全部有等价证明。按实际采用的 cut 回溯，能找到单一合法组合的分别为 8、8、6 个。原生 8 个中，7 个回到空组合；ID676 选到 #12，实际重新安装映射为 4358.646 ps，B 为 4849.164 ps，面板可行最优为 #8 的 4346.923 ps。校准后 ID73 选到 #10，回放 CEC 通过，但面积为原图的 1.08958 倍，按规则取回原图。ID103 的原生 choice 网表本身测得 1499.307 ps，可回溯组合为 0，真正返回原图为 1689.213 ps。

将无法回溯、面积超限或延迟未改善的情况按规则取回各自原图，12 电路离线推算的真实延迟／B 几何比分别是 **1.008228**（原生）和 **1.008401**（α=0.5），相对 B 同为 5 胜、3 平、4 负。该统计来自离线 full choices。零编辑的原文件和经回放序列化的文件单独计量，例如 ID676 为 4849.164 和 4358.346 ps，因此 490 ps 左右的差异不能全部归于编辑本身。

## 条件传播与联合搜索

不挂改写 choice 时，24 个原图硬传播均精确复现各自的 native mode0，重复两次相同。挂入候选共同准备后，192 个析因状态及 108 个开发状态（含 12 个原图对照）全部有 PO 时序。与同一组合单独回放后单独运行 native mode0 相比，绝对误差 ≤0.0001 原生单位的分别为 151/192 和 55/96，最大差为 12.0600 和 5.7300。共同枚举时的 cut 集与逐个映射可能不同，具体差异还需逐 cut 归因。[逐电路一致性检查](hard_parity.csv)

稀疏 CPU 与 CUDA 在 ID44、75、179、665 上全部硬评分差为 0，最大梯度差为 1.01×10⁻¹³ 以内。四例均做了松弛梯度有限差分检查，ID75、665 在该检查点的梯度为零。最大单例存储 1,625,742 个 match，最大 PyTorch allocated 显存 2.04 GiB，Slurm 批任务峰值主存 5.54 GiB。

每种方法每电路给 8 次硬组合评分。ID44/75/179 在各自的 8 个非空组合上投影；ID665 在含原图的 16 个组合上投影。逐项穷举仅在提案冻结后核验。三种方法均找到了各自面板上的代理最优值；前三个电路的随机组实际遍历了 8 个组合，所以这些面板不足以评价大搜索空间内的相对效率。
