# GPU 联合优化：目标、评价与执行记录

## 任务范围

目标原文为 [USER_GOAL.md](USER_GOAL.md)，SHA256 `11bfb57c8d1963381deba2b58692780380712dcf5119fbbbd381b3af37ba6239`。起点是 `ffd035f` 的可复现实现与 905 个历史结果，不改写这些结果。`docs/research` 是指向用户原目录 `docs/reaserch` 的兼容链接，原两份研究说明字节不变。

本轮研究主线为跨 MFFC 联合梯度选择、单电路 GPU 并行和真实 Delay–Runtime 权衡。精确 local-to-global 时序重建、完整论文算法复现、全仓库测试覆盖重审均不作为本轮主任务。没有单独授权委派，遵守 AGENTS.md 的约束，不创建子代理。

## 首轮诊断与判断规则

1. 读取固定历史样例的实际工具计时、重复 AIG、请求来源及 trace 体积，区分准备、代理/梯度、失败安装、CEC、mapping 和日志 I/O。历史计时不是新硬件的受控加速比。
2. 对 c1355、ss_pcm、DMA 做新目录中的单电路顺序冷进程基线，独立计时一个梯度策略。不能把原 pipeline 串行运行所有 baseline 的总时间与新方法单策略时间直接相除。
3. 先根据证据选择减少无效提案、减少冗余验证、减少重复传播或 GPU 计算的具体改动。每项保留可关闭的对照；不把更少的验证、隐藏离线成本、更多 mapping 请求或多 benchmark 并发叫作算法/GPU 加速。
4. GPU 对照保持同算法、输入、候选域、精度、种子和预算；检查连续值误差、离散结果、完整安装、CEC 和真实 QoR。允许 GPU 在小图/深窄图上更慢，必须报告。

## 预先固定的主评价口径

以下是本次任务自主选定的工作口径，不冒称用户已经确认论文最终阈值。若需调整，只能在冻结最终面板比较之前修改并记录原因。

- 主目标为真实 global delay，面积须不超过真实 replay no-op 的 1.05 倍；joint 模式仅作独立扩展。
- 同请求比较默认 8 个逻辑请求，含 baseline、warmup、失败与修复。另列原生 rewrite、CEC、mapping 实际调用数和缓存命中，内容相同且有完整来源链的验证复用不得记作新工具调用。
- 同时间比较以包含导入/初始化、候选/特征/推理、传输、搜索和在线真实验证的单电路 wall-clock 为准；同时给出 30/120/600 秒处的已验证 best-so-far，超过截点完成的调用不能倒填到截点。
- 达到质量所需时间的参考为：真实面积可行的 no-op 与 native ABC 中较低 delay 的 1.01 倍；native 不可用/超面积则只用 no-op。未达到明确记为未达到。
- QoR 的工作非劣判断：相对旧梯度的 delay 几何平均比不超过 1.01，90 分位比不超过 1.05，全部最终点满足面积/CEC 条件。性能目标为端到端中位加速至少 1.5 倍，或相同时间下有更好的已验证质量。未达标仍如实交付负结果。
- 新算法、GPU、梯度/局部信息与修复的贡献分别通过必要对照归属；完整时间、失败和 no-op 保留，不只展示直接梯度成功点。

开发样例固定为 c1355、ss_pcm、DMA、div、hyp、voter、Back_End_With_Decode、Division；后五项用于已知大图、深 DAG、单 MFFC 或 CEC 瓶颈诊断，不强制全部跑完整昂贵搜索。

最终面板在方法定型前按冻结数据集的输入 SHA256、来源和 AND 规模确定，排除开发设计及可识别的同名 orig/comb 家族。计划上限 16 个设计、三个预定种子（20261111、20261112、20261113），按实际诊断目的安排，不启动无目的的 905 全量重跑。905 个输入此前已用于分析，最终面板只能称冻结评价面板，不能称未见测试集。独立 CPU/GPU 大图微基准与真实端到端比较分列。
