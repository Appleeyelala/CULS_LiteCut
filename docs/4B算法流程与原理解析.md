# CULS-LiteCut（4B）最新进展、算法原理与后续研究路线图

> **给读者 / 网页端 Gemini 的背景说明**：本文档总结了我们项目的**终极研究目标**、**当前已经做到哪一步（含全量 905 电路 CPU 与 GPU 实测数据）**、**当前方法与终极目标的差距**，以及**后续达成目标的大致计划**。可以直接用于讨论算法定位、论文创新点拆解与下一步方案设计。

## 一、我们的终极研究目标是什么？

本项目面向大规模逻辑综合（AIG Rewrite），旨在解决两个紧密耦合的核心问题：

1. **多目标、多路径的端到端全局梯度联合优化（最高优先级创新点）**：
   - **什么是“多目标”**：在真实电路中，从主输入（PI）到主输出（PO）的路径数量是指数级的。优化时绝不能只盯着 1 条最慢路径（WNS），而是要**同时优化多条 PI→PO 关键与近临界路径（WNS + TNS）**，并在**扇出负载、Slew 传播与面积约束**之间做全局权衡，避免“按下葫芦浮起瓢”。
   - **什么是“多 MFFC 端到端联合梯度优化”**：将整张电路划分为多个受限局部改写区域（MFFC / 4-cut 锥），为每个区域提供多个候选替换子图，构建**准确、可微的全局时序代理模型**，在 **GPU 上通过多步梯度下降联合优化所有 MFFC 的候选选择**，直接最小化多条 PI→PO 路径的全局延迟目标，使最终 ABC Technology Mapping（ASAP7 工艺库）后的**真实全局 Critical Delay** 尽可能降低。
2. **GPU 并行加速（核心工程与系统创新点）**：
   - 将候选生成、全局时序正反向传播、多步梯度联合优化等核心阶段原生实现在 GPU（CUDA）上，把传统 CPU/Python 级优化从数十秒~数百秒压到**亚秒级（50×~100× 以上加速）**，在保证 **100% 功能等价（`cec -n`）** 的前提下使方法具备真实工业竞争力。

## 二、我们现在做到哪一步了？（当前真实进展全景）

目前我们已经完整走通了 **三个阶段**，建立起了经过 **905 个真实组合电路（ASAP7 映射 + `cec` 验证）** 检验的算法底座与 CUDA GPU 引擎：

### 阶段 1：构建并验证了“多路径、扇出与 Slew 感知的全局可微时序代理”（已完成）
早期的纯 AIG 单位层数模型（每门延迟固定算 `1`）在 `cabac_ucontext`、`c1355` 上会出现“AIG 层数变浅，但扇出暴涨导致真实映射延迟反升”的失真问题。现已迭代升级到 **`4B_v4_slew`** 模型（[aig_replay.py](../global_timing/aig_replay.py)、[select4b.py](../global_timing/select4b.py)）：
- **前向可微时序传播（考虑扇出 + PI 极性 + Slew 耦合）**：
  - 对每个 AND 门，延迟不再是 `1`，而是 $d_g = 1 + \alpha \cdot \text{load}(g) \cdot (1 + \beta \cdot s_{\text{in}}(g))$（其中 $\text{load}(g)=\max(0, \text{fo}(g)-1)$，$s_{\text{in}}$ 为输入最大出扇出 Slew）；
  - 对主输入（PI），区分正/负相位（`pi_phase_aware`），仅对需要反相器驱动的负边计入负载延迟；
- **多路径全局软敏感度反向传播（不枚举路径，线性复杂度 $O(|V|)$）**：
  - 在所有 PO 上用平滑温度 $\tau$（带自适应退火）构造全局多路径平滑目标 $\Phi = \tau \log \sum_{\text{po}} \exp(a_{\text{po}} / \tau)$；
  - 一次反向拓扑扫描即可把所有 PI→PO 路径的偏导数 $\text{sens}[v] = \partial \Phi / \partial a_v$ 精确累加到每个节点上；同时反传 Slew 耦合系数 `slew_coef`；
- **局部多路径光滑改善量 `ΔJ` + 扇出副作用扣除**：
  - 在每个候选子图内用 `LogSumExp` 衡量该锥内多条路径的综合降层量 $\Delta J$，乘以 `sens[root]` 后减去对其他扇出消费者的副作用 `side`、高扇出正则 `reg`、Slew 惩罚 `slew_cost` 与面积惩罚 $\lambda_{\text{area}} \Delta\text{AND}$；
  - 结合 `strash_aware`（结构哈希共享感知）、每节点 Top-2 备选池与动态扇出预算（`fanout_budget` + `slack_other` 硬约束），再按无冲突原则回装并做多轮滚动（3 轮）+ 可选安全门控的 `balance`/`refactor` 宏算子（补齐超长链短板）。

## 三、关键诊断：我们离终极目标还差什么？

把现状和你的终极目标（**多 PI→PO 路径多目标 + GPU 端到端多 MFFC 梯度联合优化**）对照来看，我们目前已经打牢了“**可微时序代理**”和“**毫秒级 GPU 底座**”，但还有 **3 个核心缺口** 没有闭环：

1. **最核心的算法缺口：当前还是“一阶单步敏感度 + 贪心选点”，不是真正的“多步端到端联合梯度优化”**
   - 现在的 `rw4b` 虽然用了全局反向偏导数 `sens[v]`，但每轮本质上只做了一次**一阶泰勒线性近似**（假设其他 MFFC 都不动，单个候选按 `sens * ΔJ - side` 独立打分，然后贪心排队）。
   - 这导致当多个 MFFC 同时修改时，**上下游路径之间的高阶非线性耦合**（比如上游改短后，下游多条 PI→PO 路径的竞争关系和扇出负载同时重排）无法在一次决策中联合协同优化，只能靠外层 3 轮硬改硬重算来缓慢逼近。
2. **GPU 候选质量缺口：GPU 版全集 Delay（`-3.19%`）目前还落后于 CPU 版（`-6.34%`）**
   - 原因非常明确：当前 GPU 端的 4-cut 枚举沿用了 CULS 原生的面积启发式排序（`cutVal` 只保留 8 个面积最小 cut），没有按**时序/扇出关键度**保留候选 cut；导致在 `forgeEDA` 的大量高扇出电路上，GPU 没枚举到 CPU/ABC 找到的关键提速候选。
3. **系统并行度与边界缺口**：
   - 目前 GPU 时序+枚举+打分只占不到 20% 耗时（~20ms），**约 70% 的时间花在 CPU Host 端的串行选点与重建**（~40~130ms）；
   - 全集 905 电路中还有最后 4 例在 CULS 原生 `balance`/`refactor` 内触发边界异常。

## 四、后续达成终极目标的大致研究计划（Roadmap）

不需要拘泥于具体超参，整体分 **4 个阶段** 推进，每一步都直接服务于“**多路径多目标联合梯度优化**”和“**GPU 加速**”两大核心创新点：

### 阶段 A：升级 GPU 候选生成质量（让 GPU 底座先追平并超越 CPU 版）
- **做什么**：将 `rw4b.cu` 中的 GPU 4-cut 枚举从纯面积启发式改为**时序与扇出感知的 Priority Cut**（在每个节点的 8 个 cut 槽位中，明确保留到达时间最晚/扇出瓶颈最重方向上的可压缩 cut），同时支持提取更大范围的非重叠 MFFC 区域候选。
- **预期目标**：在保持毫秒级速度的前提下，先把全量 905 电路上的 GPU 基线 Delay 从 `-3.19%` 提升至超越 CPU 版的 `-6.5%~-8%`。

### 阶段 B：核心创新——构建 GPU 原生“多路径、多 MFFC 端到端可微梯度联合优化器”
这是论文最核心的算法跃迁——把当前的“1 步一阶敏感度贪心”升级为真正的**“多步端到端联合梯度优化”**：
- **决策变量松弛**：在整张电路上选取一批互不冲突（或带冲突惩罚）的 MFFC 区域 $\{R_1, \dots, R_M\}$，每个区域 $R_m$ 有 $K_m$ 个合法候选替换子图（含“保持原样”），为其赋予连续优化参数 $\theta_m \in \mathbb{R}^{K_m}$，通过温度退火 Softmax / Gumbel-Softmax / STE 映射为候选选择概率 $p_m$。
- **多路径多目标可微全局损失**：
  $$\mathcal{L}(\theta) = \underbrace{\text{LSE}_{\tau}\!\left(\{a_{\text{po}}(\theta)\}\right)}_{\text{全局多条关键 PI}\to\text{PO 路径}} + \lambda_{\text{TNS}} \cdot \underbrace{\sum_{\text{po}} \text{SoftPlus}(a_{\text{po}}(\theta) - T_{\text{target}})}_{\text{多路径近临界总违例 TNS}} + \lambda_{\text{fo}} \cdot \text{Fanout/Slew}(\theta) + \lambda_{\text{area}} \cdot \mathbb{E}_{p(\theta)}[\Delta\text{Area}]$$
- **全 GPU 定制前向/反向联合迭代（不依赖 PyTorch 慢速构图）**：
  - 直接复用我们已经跑通的 **2ms 级 CUDA 按层前向/反向核函数**：
    1. **前向**：按拓扑层在 GPU 上同步传播每个节点的“期望到达时间、期望扇出、期望 Slew”，自然耦合所有 MFFC 候选之间的上下游相互影响；
    2. **反向**：从所有 PO 的多目标损失出发，按逆拓扑层把精确解析梯度反传回每个 MFFC 的 $\partial \mathcal{L} / \partial \theta_m$；
    3. **参数更新**：在 GPU 上用 Adam / Mirror Descent 联合迭代 $T$ 步（例如 20~50 步，温度 $\tau$ 逐步退火至离散），由于单步只需数毫秒，完整联合优化仅需 **几十到一百毫秒**；
    4. **离散化与真图回装**：取收敛后的离散候选（结合冲突检查），重建 AIG 并做 `cec` 等价验证。
- **核心价值**：真正实现“**一次联合优化同时协调全图成百上千个 MFFC、兼顾多条 PI→PO 路径与扇出/面积多目标**”，从根本上解决单步贪心看不见多点非线性耦合的短板。

### 阶段 C：全流程 GPU 加速与系统打磨
- 将 Host 端剩余的冲突消解、候选整理和 AIG 拓扑重建进一步向量化/GPU 化，把端到端耗时再压低一个台阶；
- 解决 CULS 原生宏算子在最后 4 例极端电路上的边界异常，冲击 **905/905 全通过**。

### 阶段 D：论文完整实验与严格盲测收官
- 在全量 **905 电路** 上完成论文核心对比与消融实验：
  - 对比工业基线（`abc_rewrite` / `abc_resyn2` / `CULS resyn2`）；
  - 消融验证：单位层数 vs 扇出+Slew 代理、单路径 WNS vs 多路径多目标、单步一阶贪心 vs 多步 GPU 联合梯度优化、CPU vs GPU 端到端加速比。
- 所有算法和超参最终锁定后，在严格封存的 **24 电路外部盲测集（`panel.json`）** 上做一次性最终验证，确保无过拟合、结论过硬。
