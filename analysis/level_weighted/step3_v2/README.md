# Step 3 v2：稳定软权重、两个对照方案与按 slack 的分层

## 范围与前提（先读）

- **覆盖范围没变**：只覆盖 ABC rewrite 会评估的**恰好 4 个叶子**的 cut；叶子不足 4 个的 cut（127,543 个，
  占非平凡 cut 的 41.3%）不在内。选择只发生在**每个 cut 内部**，不比较不同 cut，也不产出"每个节点的
  最终候选"。
- **v1 的软权重有数值问题，v2 修正**：v1 用未平移的 `exp(-slack/τ)`，slack≈37–38 时权重与 J 都掉到
  1e-16 量级，不同候选的 J 在数学上相等，选谁取决于浮点末位。v2 改为
  `w_l = exp(-(slack_l - m)/τ)`，`m` 是该 cut 四个叶子 slack 的最小值，argmin 不变但不再下溢；
  软权重的并列判定用相对容差 `1e-9·max(1,|J|)`，并列后仍按 `nodes_added`（self 记 0）、`subgraph`
  小者。不加权、硬权重、rootlevel、abc_default 的目标值是整数，保持精确比较。
- **局部 root_level 降低不等于全局 level 降低**：全局 level 要所有最长路径同时变短，只有联合安装后才
  能验证。本步骤只比较 cut 内部的局部指标，**不下"全局变快"的结论**。
- 本步骤没有重跑 ABC、没有重新导出候选、没有安装任何候选、没有重传播 level、没有做映射。

## 七个方案

| 方案 | 目标 | 并列规则 |
|---|---|---|
| 不加权 | `Σ leaf_depths`（未用到的叶子贡献 0） | `nodes_added`（self 记 0）→ `subgraph` |
| 硬权重 | 只加 slack 最小的叶子（并列都算） | 同上 |
| τ=0.5 / 1 / 2（平移） | `Σ exp(-(slack_l-m)/τ)·leaf_depths` | 同上，J 用相对容差判并列 |
| rootlevel | 候选的 `root_level = max(level+深度)` | 同上 |
| abc_default | 在 `accepted_by_default=1` 的候选里取 `n_nodes_saved - nodes_added` 最大者 | 并列取**先评估**者 |

`abc_default` 的三个细节：① self 候选不参与；② 没有任何 `accepted_by_default=1` 候选时，视为 ABC 在这个
cut 上不改写，按"保持原结构"处理（`root_level = node_level`、ΔAND = 0），共 **115,622** 个决策
（78.3% 的非空决策）单独计数；③ 并列取先评估者——导出里 `subgraph` 就是
`Vec_PtrForEachEntry(vSubgraphs, ..., i)` 的循环下标，即库中/评估顺序。本轮对 148,278
个决策断言了 `subgraph` 恰为 `0..n-1`，0 例外，可以据此判定"先评估"。

## 与计划不一致的地方

   无条件中止，本轮会直接失败在这 76 个已知例子上。

   `root_level` 记原 level，另有 `abc_default_keep` 列标记；统计上按"相等"计入。

   与"v1 J ≥ 1e-9"不是同一个判据；前者按 slack 定义，后者按数值。两者在 τ=0.5 上重合度最高。
4. **计划文档仍未读到**（`claude.ai/artifact/...` 区域受限），本轮按任务消息的定义实现。
5. 没有做的事：没有安装候选、没有 level 重传播、没有真实映射、没有联合替换、没有启动子代理。
