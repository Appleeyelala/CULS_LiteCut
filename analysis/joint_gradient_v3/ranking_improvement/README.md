## 诊断后只改了什么

[修改前诊断](DIAGNOSIS.md)发现：原代码两跳Region context向下游聚合，终端输出的上下文为0。ID75、179、421等电路所有PO均如此。global头虽然仍接收全电路LiteCut相对变化等汇总特征，却缺少“某个候选位于哪个输出上游”的信息。三个旧checkpoint原预测全部重现，误差0ps。

唯一修改是同一个 `20→32→32→1` 残差头的最后八维输入。对候选期望四维特征e，使用：

`context[p] = concat(tanh(sum_d S[p,d]·e[d]), tanh(sum_d R[p,d]·e[d]))`

S是**原图结构时序**对decision根节点共同逻辑相位延迟扰动的敏感性，R是原图根节点到PO的可达性。通过原结构LSE传播计算参考系数，再用GPU张量运算汇聚候选特征；不使用候选Mapping标签生成输入。S不是实际mapped criticality，也不动态重算候选引发的关键路径切换。

没有新增神经网络或参数，没有改LiteCut、结构时序、锚点、损失、优化器、搜索器和训练预算。原损失仍为PO Huber＋Critical Huber＋0.1排序项；AdamW、学习率0.001、最多200轮、patience20不变。原始入口默认行为不变，新配置显式使用 `--global-context endpoint`。权重文件记录上下文类型与源码哈希。

## 为什么暂不进入联合梯度优化

预先冻结的继续条件要求Pairwise至少增加5个百分点、Top-1不下降、平均Regret降低、最差Regret和严重反向对不增加。本轮失败于Pairwise和平均Regret，因而不启动独立新电路确认，更不运行100/905或调整搜索器。

该表示缺口确实存在，测试也确认新特征能把上游编辑信号传至终端输出，但**缺口存在不等于它是质量下降的唯一原因**。原结构先验在ID75/179已经排反，固定原图敏感性不能充分描述候选后的Mapping覆盖或关键路径变化。

另外，修改前训练集33个有定义的电路×种子中15个出现旧损失与纯组合排序梯度反向；训练集原模型Pairwise只有41.12%。本轮新表示的训练Pairwise升到48.30%，但训练平均Regret反而从2.100%升到6.895%，最差达到67.941%。这些训练结果单独列出，不混入开发表，提示当前目标与选择质量仍不一致；不能归结为单纯开发集过拟合。新模型按原规则选中的epoch为0/2/3（从0编号），本轮不事后改选epoch或延长训练。

下一项更有依据的单变量研究是**同电路组合差值/排序监督与现有绝对PO回归的目标对齐**，先验证梯度冲突能否减轻，并控制原图与serialized no-op的标签混杂。这是后续建议，本轮没有继续修改损失或启动另一套模型。需要先建立稳定排序收益，才值得将新代理接入联合梯度优化。
