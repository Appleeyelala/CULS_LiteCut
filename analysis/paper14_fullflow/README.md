# LiteCut 论文 14 电路的全流程优化基准

这 14 个电路作为后续样例。逐电路复用原始 AIG 文件，并校验论文复测时冻结的 SHA-256。[输入清单](circuits.csv) · [含各阶段时间、面积、提案和交付身份的结果表](results.csv) · [各阶段时间](stages.json) · [汇总与运行目录](summary.json)

## 测量口径

从原始 AIG 开始构造 MFFC，枚举并验证 Rewrite 候选，以冻结 Student 局部打分构造两套 ABC 映射时序模板。GPU 联合梯度搜索采用 α=0.5、种子 20261117、8 次硬评价和最多 16 个编辑。采用项目 delay 模式，只要真实映射延迟严格下降、安装和 CEC 通过，就交付新 AIG。其余情况保留原图。面积单独报告。每个电路只运行一个种子。

所有行采用同一 ASAP7 库，同一最终 ABC 评测器。原图对照不做 Rewrite。B 使用项目规定的单次 ABC Rewrite，写回 AIG 后重新读入映射。论文 LiteCut 列使用上一轮已通过 CEC 的原版 LiteCut 改写 AIG，在本轮重新做 CEC 和映射。这一列的映射器与论文复测不同。端到端墙钟从启动本项目进程到其退出，含 Python 启动、候选验证、特征提取、模板、GPU 搜索、回放与最终验证。独立对照的开销另记。

## 时间与显存

单电路端到端墙钟中位数为 675.78 秒（11.26 分钟）。b18_1_comb 用时 7,451 秒，jpeg 用时 7,807 秒。8 次硬评价之前的候选处理和模板准备也计入总时间。[各阶段原始时间](stages.json)

sc_cpu 首次在深时序图的反向负载传播阶段 CUDA OOM。PyTorch 的逐层最大值归约为求导保存了整图输入向量与输出向量。修复让归约只在本层涉及的网络上保存求导状态。保留种子、梯度目标、候选、硬评价和验收规则，从原始 AIG 重跑。其 PyTorch 峰值分配为 2.56 GiB，成功运行的 2,161.91 秒计入表内。c5315 与 bc0 的独立 CUDA 对照中，各自 8 次硬评价的向量、提案实测延迟和交付文件哈希均与修改前一致。[显存诊断和校验记录](gradient_memory.json)
