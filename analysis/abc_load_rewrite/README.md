# ABC 门级时序与联合改写的开发集验收

原始 AIG 可以从候选提取一直运行到交付通过功能等价检查的 AIG。冻结的 12 个电路上，新代理命中真实最优 1/12，平均选优损失 20.463%。原有 ABC 对数扇出代理分别为 4/12 和 2.970%。本轮保留研究入口，独立 24 电路及后续 100、905 电路的扩展门槛未达到。[逐电路选优](development.csv) · [Slurm 运行与源码快照](RUNS.json)

## 时序误差发生在哪里

同一套 Liberty 传播器在两种输入上接受检验。给它 ABC 已经选定的门、命名引脚和连线，可以逐 PO 检验上升和下降到达时间。给它一个尚未安装的联合改写，需要先估计最终有哪些门、哪些输出引脚驱动哪些输入。两步使用相同的计时函数。

| 电路与组合 | 代理关键 PO | ABC 最终关键 PO | 代理延迟 ps | ABC 最终延迟 ps |
|---|---:|---:|---:|---:|
| ID75 #6 | 124 | 90 | 264.992 | 359.195 |
| ID75 #8 | 124 | 90 | 264.992 | 404.658 |
| ID179 #1 | 6 | 3 | 9517.083 | 6917.100 |
| ID179 #7 | 6 | 3 | 7366.844 | 5987.977 |
| ID421 #1 | 0 | 0 | 19454.232 | 31105.180 |
| ID421 #7 | 0 | 1274 | 19442.389 | 94999.469 |

- **ID75**。两张真实最终网表上，#6 在 PO90 快 45.463 ps。代理在 PO124 打平，在 PO90 自身却给 #6 和 #8 分别算出 233.846 和 222.082 ps，方向已经相反。原有逐弧记录在最终关键链上观察到了 NAND3／NAND4 的区别。只修正最后如何取最大值无法解释同一 PO 上的反向。[逐输出核验](endpoints.csv) · [逐弧实测](../abc_choice_timing/arc_audit/critical_arcs.csv)
- **ID179**。代理能判对 #7 优于 #1，仍选错了最慢输出。8 选 1 时代理选 #6，真实延迟 6916.085 ps，优于它的 #7 为 5987.977 ps。单独判对这一对不足以恢复整组排序。[逐电路选优](development.csv)
- **ID421**。代理预估 #7 比 #1 快 11.844 ps，真实结果却慢 63894.289 ps。#7 在代理选中的 PO0 上也慢到 94906.438 ps。误差已经发生在该输出的到达时间估计中。具体是哪一个共享驱动、门选择或接收引脚导致错误，仍需对估计与真实网表作逐引脚对应或替换实验。[逐输出核验](endpoints.csv)
- **数值验证**。ID44、75、179 共 12 张固定网表，每台设备累计 9116 个 PO，各检验 rise 和 fall。CPU、CUDA 与导出的 ABC 单精度逐 PO 值最大差均为 0 ps。额外检查上表六张最终网表时，最早的实现曾在 ID421 的高扇出上超过原定容差。按 ABC 的实际单元顺序逐次累加单精度引脚电容后，沿用原容差，六张的 GPU 到达时间最大差均为 0 ps。此结果适用于本次库、约束和样本。面积与时延的数值误差各自记录。[固定网表逐项误差](fixed_cover_errors.csv)

## 选优口径

每个电路有 8 个冻结的非空可行组合，均有真实 CEC 和最终映射记录。评分器另算一个 no-op 以供诊断。先写完两个 α 的预测，再关联真实标签。各电路仅在 8 个组合内择优，容差内先取较少编辑，再取较小组合号。选优损失是所选组合的真实延迟除以该电路真实最优组合延迟，减一后转为百分比，最后按电路等权平均。

| 同一组 96 个非空组合 | 平均选优损失 | 命中真实最优 |
|---|---:|---:|
| 原有 ABC 对数扇出代理 | 2.970% | 4/12 |
| 新代理，无 LiteCut，α=0 | 20.463% | 1/12 |
| 新代理，有 LiteCut，α=0.5 | 20.463% | 1/12 |

LiteCut 参与时部分分数改变，12 个电路的最终选择全部相同。ID421 单电路损失为 205.414%。其余 11 个新代理的平均损失仍为 3.649%。本次数据支持把误差研究集中在估计的覆盖和连接上，尚不能把问题唯一归因到 ABC 的某一次面积恢复决策。[逐电路对照表](development.csv)

## 从原始 AIG 到交付文件

1. 读入原始 AIG，构造 MFFC partition，用 gpuls 提取 Rewrite Decision 和 Replacement Candidate。验证候选真值及重用约束，建立同根和跨根冲突。带 LiteCut 的配置按已有 Student 给原局部和候选分别评分。
2. 原图完整映射一次并得到基准。将每个可变根的原结构和所有允许的替代结构放入同一局部模板集合，调用 ABC 的延迟优先与面积恢复两次模板映射。两个模板映射单独计数。跨越模板边界的真实全网门组合可能缺失。
3. 对给定候选向量反向累加活动接收引脚的负载，前向按 Liberty 表计算上升／下降到达时间与 slew。按 required time 和预估面积流在两种局部覆盖间选择，再用组合后的连线重新计时。支持负单调、正单调、非单调弧，缓存对所有选择都不变的门时序。可微评分在当前离散覆盖上反传，覆盖切换本身没有梯度。
4. 梯度法在各根的候选概率上更新 logits，以合法离散向量参与择优。α=0 跳过 Student。α=0.5 将候选与原结构局部预测的比值开平方，作用于候选边界的末级驱动延迟。这里借鉴 AiMap 的局部校正思路，运行时依赖 ABC、现有 Student 和 gpuls。
5. 冻结一个联合提案，实际安装、检查安装完整性，进行接口按位置对应的 CEC，最多一次完整候选映射。delay 模式要求严格降低真实延迟，area 模式另要求面积比 ≤1.05。输出的 `result.json` 同时记录提案和返回结果，`selected.aig` 附 SHA-256。单个 AIG、多个输入和预备候选目录均有入口。

在已分配 GPU 的 Slurm 作业中，从不可变快照的父目录运行下例。配置内为本集群已验证的工具绝对路径。将多个 AIG 传给 `--original` 会生成每个输入的结果和 `batch.json`。同一原图可以用 `--prepared <已有输出>/prepared` 重用候选目录。[入口代码](../../scripts/load_rewrite.py) · [工具配置](../../config/load_rewrite_tools.json)

```bash
export LD_LIBRARY_PATH=/usr/local/cuda-11.8/lib64:${LD_LIBRARY_PATH:-}
python -B src/scripts/load_rewrite.py --tools src/config/load_rewrite_tools.json \
  --original input/design.aig --output "$PWD/output/design" \
  --mode delay --device cuda --method gradient --alpha 0 --steps 8
```

## 搜索对照与资源

c1355 和 ID75 分别有 1815、2920 个 decision，以及 9940、12626 个独立根选项累计状态。三种方法使用相同输入、种子和合法性约束。一次对照给 8 次硬评价，另一次给 3 秒搜索时间，在步与步之间检查时间，已启动的一步可以跨过截止时间。每次从原始 AIG 启动独立进程，端到端墙钟包括进程启动、模板准备、搜索和最终检查。[12 次搜索逐项记录](raw_controls.csv)

| 原始输入 | 固定 8 次评价 | 固定 3 秒搜索 |
|---|---|---|
| c1355，原图 360.111877 ps | 梯度提案 375.918823 ps，返回原图。贪心返回 360.111603 ps，差 0.000274 ps。随机提案 364.149231 ps，返回原图。 | 三者均返回原图。 |
| ID75，原图 372.744080 ps | 梯度提案 376.124481 ps，随机提案 375.804047 ps，两者均返回原图。贪心选择 no-op。 | 梯度与贪心返回原图。随机返回 358.551422 ps，面积比 1.0390，CEC 通过。 |

以上两种 GPU 搜索预算下，梯度方法均未交付改善。随机在 ID75 的单次收益可证实该输入存在可安装的好组合，单种子和两个电路还不足以估计任何方法的总体胜率。搜索可能在固定电路组成上走得更快，但研究目标仍需以实际交付和时间共同验收。

另做了同一节点、同一种子、8 次硬评价的 CPU／CUDA 对照。两种设置都使用 GPU 提取候选，只切换全局计时和优化设备。c1355 的搜索耗时分别为 9.22／12.07 秒，端到端为 17.83／22.07 秒，两次交付相同。ID75 的搜索耗时分别为 6.78／5.11 秒，端到端为 16.65／16.49 秒。CPU 提案 367.830 ps 通过验收，CUDA 提案 376.124 ps 回退到原图 372.744 ps。轨迹上第一次更新后有四个 decision 不同，之后六步的硬提案相同。每个设备每个电路各一次，本轮未证明稳定端到端加速。[设备对照](device.csv)

三种搜索预算对照中的最高 PyTorch CUDA allocated 为 65.7 MiB，最高 Python 进程 RSS 为 1.60 GiB。设备上下文和外部 gpuls 的 GPU 显存不在 PyTorch 统计中。清理本轮 ABC 编译产生的 2672 个对象与依赖文件，回收 271.2 MiB，运行用二进制的 SHA-256 清理前后一致。

## 交付验收

- 最终回归总计 227 项，208 项通过，19 项因可选历史集成夹具条件跳过。另在真实工具上验证了 raw/batch、prepared 与 raw 的提案及返回哈希一致、无候选只映射原图一次、非空提案最多两次整图映射、返回文件哈希和功能等价性。
- 固定交付夹具 ID676 的 #12 从 4849.164 降到 4358.646 ps，面积比 0.98784，交付候选。ID73 的 #10 从 270.054 升到 291.403 ps，面积比 1.08958，在带面积约束和仅延迟两种模式下分别触发相应的回退。固定夹具的改善只验证交付规则，不计作梯度搜索收益。
- 当前未建立跨边界物理覆盖的可靠预测。下一项可证伪的研究是在 ID75 的 PO90、ID421 的 PO1274 回放真实网表，将逐段真实驱动和接收引脚代入代理，观察哪个最小替换能恢复组间时差。应先保留每段负载、slew 和 rise/fall 差异，再决定扩展候选映射边界的位置。
