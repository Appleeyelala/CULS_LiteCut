# 端到端速度与耗时来源

## CPU 与 GPU 全局计算

同一 A40 节点、单个 PyTorch CPU 线程、每次从原始 AIG 启动新进程。两种设备都调用原生 GPU 候选枚举和改写回放。每个小电路、每种设备各运行两次，交替顺序。完整墙钟包含 Python 启动、Student、模板准备、最后的回放、映射与 CEC。

| 电路 | CPU 全流程两次 s | GPU 全流程两次 s | 平均端到端加速 | CPU / GPU 平均搜索 s |
|---|---:|---:|---:|---:|
| c5315 | 59.54 / 56.32 | 52.41 / 50.55 | 1.13× | 23.43 / 14.93 |
| intra_pred_PE | 209.22 / 229.97 | 149.24 / 150.68 | 1.46× | 109.42 / 32.48 |

两电路的八次运行都复现各自历史的完整编辑向量和交付 AIG 字节。完全从原始 AIG 跳过 Student 另跑一遍，`c5315` 的时间为 38.03 s，交付 420.90 ps；`intra_pred_PE` 为 88.66 s，交付 1366.60 ps。这两行只有一次冷进程观测。单次原生 ABC Rewrite 的历史时间和质量在开发集基线表中单列。

## 大模板解析

原解析器对每个门的输出在线性输入引脚列表中做成员检查，还会反复扫描多行端口声明已经拼接的前缀。对引脚建立集合，并按行收集声明后一次合并。在相同初始和面积恢复 Verilog 上逐文件校验有序输入、输出、门类型及连接，四个指纹全部相同。

| 电路 | 两份文件旧 / 新解析 s | 独立解析加速 | 原 / 新全流程 s | 全流程加速 | 新流程交付 |
|---|---:|---:|---:|---:|---|
| b18_1_comb | 4350.6 / 48.9 | 88.9× | 7451.27 / 2683.74 | 2.78× | 原图，5000.53 ps |
| jpeg | 4531.3 / 58.1 | 77.9× | 7806.91 / 2666.96 | 2.93× | 原图，18912.98 ps |

这两个大电路的端到端旧、新版本各一次。纯解析对照最便于归因到 CPU 实现。全流程计时包含其他源码版本和节点负载差异。`b18_1_comb` 的搜索向量与交付文件都复现。`jpeg` 的新提案为 18919.63 ps，历史提案为 18937.46 ps，两次都未通过延迟验收，最终文件一致。最新实现中，Student 分别占 975.6 s 和 846.3 s，模板准备占 953.2 s 和 1078.2 s；其中构造时序计算图本身分别耗时 434.6 s 和 530.0 s。八步搜索分别约 107.3 s 和 107.8 s。这为下一轮工程优化给出了具体的时间预算。
